# Please explain vector databases. If you were to select a vector database for a hypothetical problem (you may define the problem) which one will you choose, and why?

Vector database refers to the type of database where the storage, management, and querying of vector embeddings are done.

Unlike conventional databases where the search process is carried out by looking for the exact match by using the keyword or value, a vector database can also look for information based on similarity in meaning, irrespective of the actual words used.

## Hypothetical Problem

A multi-tenant B2B SaaS that offers an AI support assistant. Each customer (tenant) uploads their docs, and the assistant answers questions via RAG. Scale: ~500 tenants, ~30M chunks total, tenant sizes wildly uneven (a few have millions of chunks, most have thousands).

## Which Vector Database Would I Choose?
My choice: Qdrant

Why Qdrant:

Filtering is a first-class feature. Its filterable HNSW handles payload filters during graph traversal rather than as a slow pre- or post-filter step. In multi-tenant RAG, almost every query is filtered, so this is the deciding factor.
Multi-tenancy support. A single collection with a tenant-ID payload index (it has an explicit tenant-optimized index option) scales better than 500 separate collections, with the option to shard large tenants separately.
Hybrid search. Native sparse and dense vector support with fusion means I don't need a second system for BM25.
Memory control. Scalar and binary quantization, with on-disk vectors and an in-RAM index, keep 30M vectors affordable.
Operational simplicity. It is a single Rust binary with a managed cloud option, so a small team can start on Qdrant Cloud and self-host later if costs demand it.
